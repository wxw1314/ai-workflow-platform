# 审批请求与持久化状态机

- **计划 ID：** EC-041
- **所属阶段：** 第5周
- **优先级：** P0
- **依赖：** EC-040
- **状态：** 未开始

## 1. 目标与用户价值

为调价/促销建立服务端持久化人工审批请求。

## 2. 功能范围

### 本次包含
- approval_requests/approval_actions。
- 状态：pending、approved、rejected、expired、executing、succeeded、failed（按实现需要约束转换）。
- 保存 action type、target、规范化 payload、hash、requester、approver、tenant、过期时间。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用 PostgreSQL、用户身份、LangGraph checkpoint；审批数据不放 Milvus。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

审批模型、迁移、创建/查询/批准/拒绝 API 和状态转换 Service。

## 5. 业务规则与边界条件

创建请求不等于批准；禁止非法状态回退；过期不可批准；拒绝必须记录原因；payload 变更需新请求。

## 6. 安全、权限与隐私

审批 API 强制角色和 ownership；防越权审批、重放、CSRF/请求伪造；审计记录不可由普通用户修改。

## 7. 人工审核 / 人工介入

必须人工审批；建议启用请求人与审批人分离，至少禁止请求人自批（可配置明确例外并审计）。审批界面展示变更前后值、影响对象、风险、数据时间戳。

## 8. 异常与恢复

并发审批、重复点击、请求过期、事务中断、重复请求。

## 9. 测试要求

状态机非法转换、并发更新/乐观锁、自批、越权、过期、hash 篡改测试。

## 10. 验收标准

审批全程持久化，只有授权审批人可审批，状态转换可审计。

# 执行审计与操作历史

- **计划 ID：** EC-043
- **所属阶段：** 第5周
- **优先级：** P0
- **依赖：** EC-041, EC-042
- **状态：** 未开始

## 1. 目标与用户价值

建立可追溯的审批、执行和关键业务操作记录。

## 2. 功能范围

### 本次包含
- audit_logs 记录 actor、tenant、action、resource、timestamp、result、request_id。
- 保存必要请求/响应摘要和错误分类。
- 提供只读审计查询。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用现有结构化日志和 request_id；Langfuse 仅用于 tracing，不代替审计。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

审计模型、写入服务和只读查询 API。

## 5. 业务规则与边界条件

审计记录不可被普通业务 API 修改/删除；不记录完整密钥、Token 或不必要个人信息。

## 6. 安全、权限与隐私

审计查询本身做 ownership/角色校验；敏感字段脱敏；防日志注入。

## 7. 人工审核 / 人工介入

审批、拒绝、过期、执行尝试和结果都必须写审计；写入失败时对高风险动作 fail closed。

## 8. 异常与恢复

审计写入失败、重复事件、异步任务延迟。

## 9. 测试要求

审计完整性、越权查询、敏感信息扫描和失败关闭测试。

## 10. 验收标准

关键动作有完整操作者、时间、对象、结果和关联 ID。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

# 自有商品数据模型与 CRUD

- **计划 ID：** EC-010
- **所属阶段：** 第2周
- **优先级：** P0
- **依赖：** EC-003, EC-004
- **状态：** 未开始

## 1. 目标与用户价值

提供可维护的自有商品主数据。

## 2. 功能范围

### 本次包含
- 商品/SKU 基础信息、平台标识、状态、成本/售价必要字段。
- CRUD API、分页筛选和详情查询。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用 SQLModel、鉴权、API schema 和自动生成 SDK 流程。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

products 模型及 CRUD API；成本字段需定义生效时间/版本。

## 5. 业务规则与边界条件

SKU 唯一性按租户与平台范围定义；软删除/停用语义明确；不可把竞品商品混入自有商品表。

## 6. 安全、权限与隐私

所有读写校验 ownership；成本和供应商信息按最小权限返回；输入长度与枚举白名单。

## 7. 人工审核 / 人工介入

本功能不触发外部写操作。

## 8. 异常与恢复

并发更新、重复 SKU、无效平台标识、已关联数据停用。

## 9. 测试要求

CRUD、分页上限、跨租户 IDOR、唯一约束和迁移测试。

## 10. 验收标准

商品可新增/查询/修改/停用；越权访问失败；历史关联不被意外级联删除。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

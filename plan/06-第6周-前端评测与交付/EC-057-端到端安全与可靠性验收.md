# 端到端安全与可靠性验收

- **计划 ID：** EC-057
- **所属阶段：** 第6周
- **优先级：** P0
- **依赖：** EC-050..EC-056
- **状态：** 未开始

## 1. 目标与用户价值

对四个核心演示场景做端到端验证，检查权限、安全、异常恢复和数据真实性。

## 2. 功能范围

### 本次包含
- 端到端演练四个场景。
- 验证租户隔离、Prompt Injection、CSV 安全、SSE 取消、审批门禁、幂等和审计。
- 检查模型成本、超时和最大步数。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用现有测试、Langfuse、SSE 和数据库。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

验收报告、问题清单和修复记录。

## 5. 业务规则与边界条件

测试环境与生产配置分离；Demo Adapter 默认启用；真实平台写接口默认关闭。

## 6. 安全、权限与隐私

覆盖 IDOR、越权审批、密钥泄露、SSRF、注入、恶意文件、日志脱敏和速率限制。

## 7. 人工审核 / 人工介入

验证所有外部写操作均需有效人工审批；审批后仍重新校验；未审批执行率必须为 0。

## 8. 异常与恢复

第三方服务不可用时使用 Mock；区分环境故障和产品缺陷。

## 9. 测试要求

完整 E2E、故障注入、权限矩阵、迁移和回归测试。

## 10. 验收标准

四个场景可重复演示；高危安全问题关闭；未解决风险有明确说明。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

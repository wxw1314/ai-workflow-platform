# Agent 评测集与自动化回归

- **计划 ID：** EC-056
- **所属阶段：** 第6周
- **优先级：** P0
- **依赖：** EC-035, EC-036
- **状态：** 未开始

## 1. 目标与用户价值

用固定任务集衡量 Agent 的工具选择、证据、数值和安全行为。

## 2. 功能范围

### 本次包含
- 建立 50 条左右任务集起步（可逐步扩展）。
- 覆盖销量下降、竞品降价、定价、RAG 无命中、工具故障、越权写操作。
- 数值与审批策略使用确定性断言；LLM Judge 只作辅助。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用 Langfuse Dataset/Tracing；测试环境使用固定数据。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

评测脚本、指标报告和回归门槛。

## 5. 业务规则与边界条件

评测输入/期望输出版本化；模型随机性需控制；不能只报告平均分掩盖安全失败。

## 6. 安全、权限与隐私

评测数据脱敏；禁止使用真实密钥；未审批写操作目标为 0。

## 7. 人工审核 / 人工介入

包含“用户要求直接调价但未审批”的负向测试；任何成功执行均判失败。

## 8. 异常与恢复

模型供应商/版本变化、工具数据漂移、评测不稳定。

## 9. 测试要求

工具选择/参数、数值准确率、证据完整性、策略合规、延迟和成本。

## 10. 验收标准

有可重复报告；关键数值正确；未授权写操作为 0；失败用例可定位。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

# 经营分析报告生成与 SSE 事件

- **计划 ID：** EC-036
- **所属阶段：** 第4周
- **优先级：** P1
- **依赖：** EC-030, EC-035
- **状态：** 未开始

## 1. 目标与用户价值

向用户输出结构化分析报告，并展示 Agent 执行过程。

## 2. 功能范围

### 本次包含
- 报告包含结论、关键指标、证据、推断、限制和建议。
- 扩展现有 SSE 事件（如 evidence/report），兼容已有事件。
- 前端可停止执行。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用现有 SSE、token/tool_start/tool_end/error/tool_retry/done 和取消传播。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

报告 DTO、事件 schema、流式输出。

## 5. 业务规则与边界条件

不能把模型推断标为事实；事件顺序和终态明确；断连不代表业务写操作回滚（当前流程只读）。

## 6. 安全、权限与隐私

SSE 需鉴权和 ownership；限制事件大小；不输出密钥或完整敏感数据。

## 7. 人工审核 / 人工介入

报告建议不能直接触发执行；用户后续明确选择也必须走审批模块。

## 8. 异常与恢复

断连、重复事件、取消、服务重启和超大报告。

## 9. 测试要求

事件兼容、断连取消、报告证据完整性和前端解析测试。

## 10. 验收标准

用户能看到执行过程和结构化报告，旧 Agent 页面不回归。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

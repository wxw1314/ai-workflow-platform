# 电商经营知识库接入

- **计划 ID：** EC-034
- **所属阶段：** 第4周
- **优先级：** P1
- **依赖：** 现有 RAG、EC-030
- **状态：** 未开始

## 1. 目标与用户价值

复用现有 RAG，建立经营规则和产品资料检索入口。

## 2. 功能范围

### 本次包含
- 规划知识库分类：产品资料、定价策略、经营规范、历史报告。
- 接入现有 search_business_knowledge Tool。
- 检索结果带文档来源和片段定位。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用现有 KnowledgeBase、Document、Chunk、Embedding、Milvus 检索和 ownership。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

知识库配置/分类、检索 Tool 和数据导入说明。

## 5. 业务规则与边界条件

RAG 结果是参考材料而非业务事实；无命中必须明确说明；文档版本/过期需可见。

## 6. 安全、权限与隐私

文档内容视为不可信输入，防 Prompt Injection；检索严格校验 KB ownership；上传沿用文件安全限制。

## 7. 人工审核 / 人工介入

知识库不能审批或授权写操作；文档中“指示 Agent 执行操作”不得生效。

## 8. 异常与恢复

无命中、重复文档、过期规则、恶意指令、检索服务失败。

## 9. 测试要求

跨租户检索、Prompt Injection、无命中和引用正确性测试。

## 10. 验收标准

Agent 能引用经营规则，且不会把文档指令当系统指令。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

# 电商智能经营分析与决策 Agent｜6 周总开发规划

## 项目目标

基于现有 AI Workflow Platform
继续迭代，建设一个面向电商经营场景的智能分析与决策
Agent。用户通过自然语言提出经营问题，Agent
能够结合自有商品经营数据、竞品数据和企业知识库进行分析，给出有数据依据的建议；涉及调价、促销等实际业务操作时，经过人工审批后再执行。

## 现有基础

本计划以已有项目为起点，不重复建设已经具备的能力：

-   **后端与数据层：** FastAPI、SQLModel、PostgreSQL
-   **Agent：** LangChain、LangGraph、ToolNode、异步工具调用、多轮会话与
    Checkpointer
-   **RAG：** 知识库管理、文档解析、Chunk、Embedding、Milvus 检索
-   **流式交互：** SSE、工具调用状态、错误和重试事件、主动停止
-   **可靠性：** 应用层重试、异常处理、取消传播
-   **可观测性：** Langfuse Trace，已有基础 RAG Evaluation Dataset
-   **前端：** React、TanStack Router/Query、Shadcn UI，已有 Agent
    对话页面和基础工作流界面

实际开发前，以代码仓库现状为准核对已有实现和待补缺口。

## 最终验收目标

六周结束时，项目应能够完整演示以下业务闭环：

1.  用户询问某商品近期销量下降的原因，Agent
    能查询经营数据、分析变化并给出证据。
2.  用户追问竞品是否降价，Agent
    能查询竞品历史快照并分析价格变化与自有商品表现之间的关系。
3.  用户询问是否应该跟价，Agent
    能结合成本、毛利约束、竞品价格和企业规则，计算并比较定价方案。
4.  用户选择某个方案后，Agent
    创建审批请求；审批通过后才执行模拟调价，并记录执行结果和审计信息。

## 项目实施原则

-   以现有项目为基础迭代，优先复用已经完成的
    Agent、RAG、SSE、Checkpointer、Retry 和 Langfuse 能力。
-   先保证业务数据和分析结果可信，再扩展 Agent 能力与前端功能。
-   SQL 查询、指标统计、毛利计算和阈值检测由确定性代码完成；LLM
    负责理解问题、规划工具、综合证据和生成建议。
-   竞品数据必须标明来源与采集时间；不可观测的竞品销量、利润等指标不得编造。
-   调价、促销等外部写操作必须经过人工审批。
-   六周计划是阶段性总规划，具体任务、接口、数据字段和技术实现方案在每周启动时再进一步拆分。

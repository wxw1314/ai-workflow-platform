# 通用安全与边界规范

本文件适用于所有功能计划；若单个计划提出更严格要求，以更严格者为准。

## 身份与数据隔离

- 所有业务查询从服务端可信身份上下文获取 user_id/tenant_id，不能信任客户端传入的归属字段。
- 查询、更新、删除、导入、导出、Agent Tool、后台任务均须做 ownership 校验。
- 不允许通过猜测 ID 访问其他用户/租户资源；测试跨租户 IDOR。
- 管理员能力必须有明确角色和审计，不以“内部接口”作为跳过鉴权理由。

## 输入与数据完整性

- 使用 Pydantic/SQLModel schema 校验；限制字符串长度、列表数量、时间范围、文件大小和分页上限。
- 金额使用 Decimal/Numeric，显式币种；时间统一存 UTC，展示时明确时区。
- CSV 导入防止公式注入（以 `=`, `+`, `-`, `@` 开头的单元格）；限制行数、列数和文件大小。
- 文件上传校验扩展名、MIME、文件签名，防止路径穿越；解析放在受控目录，设置资源限制。
- 外部 URL 不允许由用户任意指定后直接抓取；防 SSRF，阻止 localhost、私网、链路本地和云元数据地址，并限制重定向。

## Agent 与工具安全

- Tool 参数必须强类型、有限范围；工具内部再次验证用户/租户权限。
- 不向模型暴露任意 SQL、任意 Python、任意 shell、任意 URL fetch 工具。
- 把 RAG 文档、网页、竞品描述视为不可信输入；防 Prompt Injection。文档内容不能覆盖系统策略或触发写操作。
- 只把完成当前任务所需的最小数据交给模型；对外部文本做长度限制和必要脱敏。
- 工具结果必须包含来源、时间范围、数据新鲜度和缺失字段；证据不足时明确说明。
- LLM 不能决定审批是否通过，也不能自行调用执行适配器。

## 人工审批与外部写操作

- 写操作 Tool 只允许创建待审批请求，不直接调用平台写接口。
- 审批状态由服务端持久化，状态流转受约束；前端按钮不能直接改变最终业务状态。
- 审批记录至少包含：动作类型、目标对象、规范化 payload、payload hash、请求人、审批人、租户、创建/过期时间、状态、拒绝原因。
- 审批人不得仅凭模型摘要审批；界面展示目标对象、变更前后值、影响范围、风险和数据时间戳。
- 批准后重新校验权限、参数、目标当前状态、价格/成本版本、审批有效期和 hash。
- 执行使用幂等键；重复请求不得重复调价/发布；超时后先查询执行状态，不盲目重试非幂等操作。
- 高风险动作可要求二次确认或双人审批；第一版至少支持请求人/审批人身份记录及禁止自批策略（若业务场景启用审批分离）。
- 任何外部写操作默认使用 Demo Adapter；真实平台适配器必须单独授权、配置开关、限额和测试。

## 日志、密钥与可观测性

- 密钥只放服务端环境变量/密钥管理，不进前端、不进仓库、不进日志。
- 业务审计日志与 Langfuse Trace 分离；审计记录不可由普通用户修改。
- 日志记录 request_id、actor、资源 ID、动作、结果和错误类别，避免记录完整敏感内容。
- 设定模型调用超时、Token/成本上限、工具调用次数上限和 Agent 最大执行步数。

## 可靠性与数据质量

- 对读请求可按错误类型有限重试；对写操作必须先确认幂等性。
- 后台任务具备状态、重试次数、错误摘要、租户归属和幂等键。
- 缺失数据不得默认为 0；数据延迟需显式标注。
- 竞品数据必须记录来源和采集时间；不可观测指标不允许填充推测值。

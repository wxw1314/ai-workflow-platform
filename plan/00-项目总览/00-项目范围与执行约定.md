# 项目范围与执行约定

## 产品目标

用户通过自然语言提出电商经营问题，Agent 结合自有商品经营数据、竞品数据和企业知识库完成诊断、竞争分析与策略建议。涉及调价、促销等外部写操作时，必须经过人工审批后才能执行。

## 第一阶段必须跑通的业务场景

1. 商品销量诊断：查询销售、流量、转化、库存、价格和促销数据，说明结论证据。
2. 竞品影响分析：查询竞品历史快照，对比自有商品价格与表现，不把相关性说成因果关系。
3. 定价方案分析：查询成本、售价、毛利规则和竞品价格，由代码计算多个方案。
4. 审批后执行：创建审批请求，审批通过后执行模拟适配器并记录审计结果。

## 明确不做

- 完整 ERP、订单履约系统或全平台店铺管理系统。
- 覆盖所有平台的通用爬虫。
- 绕过登录、验证码、付费墙、访问限制或平台反爬机制。
- 推测或伪造竞品真实销量、利润、库存、转化率。
- Agent 自由生成 SQL、任意 URL 抓取或任意工具执行。
- 未审批的调价、促销发布、批量通知。
- 第一版 Multi-Agent。

## 现有能力复用清单

FastAPI、SQLModel、PostgreSQL、LangChain、LangGraph、ToolNode、异步工具、多轮 Checkpointer、RAG、Milvus、SSE、重试/取消、Langfuse、React、TanStack Router/Query、Shadcn UI。开发前需核验仓库当前状态，不将历史进度直接当作当前事实。

## 每个功能的执行流程

1. Codex 只读检查相关模块、模型、路由、迁移和测试。
2. 输出“现状、缺口、拟修改文件、风险、测试方案”，等待确认后实施。
3. 只实现当前计划文件范围内的功能。
4. 添加单元/集成测试和必要的迁移。
5. 运行相关测试、lint、类型检查；记录真实结果。
6. 更新本文件验收记录。未通过项明确列出，不得标记完成。

## 完成定义（DoD）

- 功能满足本文件验收标准。
- 正常路径、边界路径、权限失败路径均有测试。
- 日志不包含密码、Token、API Key、完整敏感请求体。
- 数据迁移可升级；有破坏性变更时说明回滚策略。
- API 有输入校验、分页/上限、错误语义和 ownership 校验。
- 不存在未经审批的外部写操作。
- 文档与实际代码一致。

# 现有系统安全基线审计

- **计划 ID：** EC-001
- **所属阶段：** 第1周
- **优先级：** P0
- **依赖：** EC-000
- **状态：** 已完成（2026-11-27）

## 1. 目标与用户价值

在扩展电商业务前识别鉴权、租户隔离、密钥、文件和 Agent 风险。

## 2. 功能范围

### 本次包含
- 检查认证与角色。
- 检查业务资源 ownership。
- 检查上传、日志、外部 URL、Tool 权限和密钥配置。
- 建立风险等级与修复建议。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用现有认证依赖、日志和配置体系。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

输出安全审计清单，不在本任务中大规模修复。

## 5. 业务规则与边界条件

发现高危问题先阻断依赖该能力的功能；不要将 UI 隐藏当作安全控制。

## 6. 安全、权限与隐私

禁止泄露 Token/API Key；测试 IDOR、越权访问、Prompt Injection 和 SSRF 风险。

## 7. 人工审核 / 人工介入

若发现任何可直接执行外部写操作的现有路径，必须先关闭或加服务端审批门禁。

## 8. 异常与恢复

审计误报需用测试或代码路径确认；问题无法复现时标为待验证。

## 9. 测试要求

匿名访问、跨用户/租户访问、无效 token、恶意 URL、超大输入和日志脱敏测试。

## 10. 验收标准

形成带优先级、影响范围、复现方式和建议的安全清单。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

# 竞品数据源 Provider 接口

- **计划 ID：** EC-024
- **所属阶段：** 第3周
- **优先级：** P1
- **依赖：** EC-020, EC-021
- **状态：** 未开始

## 1. 目标与用户价值

将数据来源与业务模型解耦，便于后续替换授权数据源。

## 2. 功能范围

### 本次包含
- 定义统一 Provider 输入/输出协议。
- 输出标准化价格、币种、来源、时间、状态和错误。
- 明确同步/异步边界与超时。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用当前 HTTP 客户端、重试和配置体系；不新增不必要框架。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

Provider Protocol/抽象、标准 DTO 和错误类型。

## 5. 业务规则与边界条件

Provider 不拥有业务写权限；不允许传入任意目标 URL；每个来源需独立限流和超时。

## 6. 安全、权限与隐私

SSRF 防护、域名 allowlist、TLS 校验、密钥服务端保存；禁止绕过平台访问限制。

## 7. 人工审核 / 人工介入

采集只写本地快照；外部业务写操作不属于 Provider。

## 8. 异常与恢复

来源超时、429、数据结构变化、空结果和部分字段缺失。

## 9. 测试要求

契约测试、超时/限流测试、恶意 URL 拒绝测试。

## 10. 验收标准

Provider 可替换，业务层不依赖特定平台字段。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

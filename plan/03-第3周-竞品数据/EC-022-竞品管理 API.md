# 竞品管理 API

- **计划 ID：** EC-022
- **所属阶段：** 第3周
- **优先级：** P1
- **依赖：** EC-020, EC-021
- **状态：** 未开始

## 1. 目标与用户价值

提供竞品与关联商品的管理接口。

## 2. 功能范围

### 本次包含
- CRUD、分页、筛选、关联/取消关联。
- 只读快照列表。

### 本次不包含
- 不重建现有 FastAPI、Agent、RAG、SSE、Checkpointer、Milvus 或前端基础设施。
- 不实现本文件未列出的相邻业务功能。

## 3. 现有能力复用与代码检查

复用 API 鉴权、schema、分页和错误规范。

Codex 必须先检查当前仓库真实代码、模型、路由、迁移和测试；不得凭计划臆造文件路径或重复造轮子。

## 4. 数据与接口

竞品管理 API。

## 5. 业务规则与边界条件

删除竞品时保留历史快照或按明确归档策略处理；禁止级联误删自有商品。

## 6. 安全、权限与隐私

所有对象做 ownership；限制 URL/文本长度；对外返回字段白名单。

## 7. 人工审核 / 人工介入

本功能不触发外部写操作。

## 8. 异常与恢复

重复关联、关联对象不存在、跨租户 ID、历史快照存在时删除。

## 9. 测试要求

API 集成、IDOR、约束冲突和历史保留测试。

## 10. 验收标准

竞品管理完整，历史数据不因普通删除意外丢失。

## 11. Codex 执行约束

1. 先只读检查并汇报现状、差异、拟修改文件和风险。
2. 等待确认后，仅实施本计划范围。
3. 先补测试，再实现或同步实现；不得删除已有测试来通过检查。
4. 不得修改自动生成的 OpenAPI SDK 文件；如 API schema 变化，按项目既定流程重新生成。
5. 汇报实际修改文件、迁移、测试命令和真实测试结果。

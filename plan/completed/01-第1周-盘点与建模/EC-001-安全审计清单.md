## 2. 风险清单

### P0 — 阻断级（必须先处理，处理前不得开发依赖认证/审批的新功能）

**P0-1 真实密钥已提交进 Git 仓库**
- 证据：`git ls-files` 显示 `.env` 被跟踪；`git log --oneline -- .env` 有 4 次提交（`110ab42`、`4cb8461`、`2dcd6f1`、`329746d`）。
- 涉及键名（仅名称）：`SECRET_KEY`、`DATABASE_URL`、`FIRST_SUPERUSER_PASSWORD`、`BAIYOU_API_KEY`、`DASHSCOPE_*`、`MILVUS_TOKEN`、`LANGFUSE_SECRET_KEY`。
- 影响：任何拿到仓库历史者可伪造 JWT（等同任意用户/超管）、调用付费模型与向量库。
- 复现：`git show 2dcd6f1:.env`（**严禁在审计输出中展示内容**）。
- 建议：轮换全部密钥 → `git rm --cached .env` → `git filter-repo` 清理历史 → 新增 `.env.example`（仅键名）。

**P0-2 `backend/app.db` 被 Git 跟踪**
- 证据：`git ls-files` 含 `backend/app.db`；`sqlite3 .tables` 显示 `user`、`item`，`user` 表 2 行（密码哈希）。
- 建议：确认非线上库后移除跟踪、清理历史；与 P0-1 一并轮换相关口令。

**P0-3 `/private/users/` 无鉴权用户创建接口**
- 证据：`routes/private.py:23-38`（无依赖鉴权、无邮箱唯一校验、无密码强度校验）；`api/main.py:29-30` 仅在 `FASTAPI_ENV == "development"` 时挂载。
- 影响：环境变量配置失误即暴露"任意创建用户"接口；即使开发环境也污染用户表。
- 建议：删除该路由，或改为显式本地开关 + 超管鉴权 + 复用 `UserCreate` 校验。

### P1 — 高危（影响 Agent / 审批类后续功能）

**P1-1 JWT 不可吊销**
- 证据：`core/security.py` 仅签发 `exp/sub`；无 `token_version`/jti 黑名单；`ACCESS_TOKEN_EXPIRE_MINUTES = 8 天`。
- 影响：改密码、删账号后旧 Token 仍有效 8 天。后续审批、调价必须能立即吊销身份。
- 建议：`User.token_version` + 签发/校验比对；或 Redis 注销列表。

**P1-2 无限流 / 无配额**
- 证据：`login/access-token`、`signup`、`password-recovery`、`/ask`、`/agent`、`/agent/stream` 均无速率限制。
- 影响：撞库、邮箱轰炸、付费 LLM/Embedding 额度耗尽（成本型 DoS）。每次 `/agent` 都是一次付费模型调用。
- 建议：按 IP + 用户双维度限流；为 LLM 调用设日/月配额与 `max_tokens` 上限。

**P1-3 登录计时侧信道（部分缓解）**
- 证据：`crud.py:64-79` 仅在用户不存在时走 DUMMY_HASH，存在时直接 `verify_password`，两条路径哈希代价不同。
- 影响：可测出邮箱是否注册。
- 建议：统一先查库再恒定代价校验，或接受并登记。

**P1-4 上传仅校验扩展名**
- 证据：`document_service.py:13-24` 仅 `Path(filename).suffix`；无 MIME/魔数校验；解析（`document_parser.py`）无超时、无解压炸弹防护；错误文案写 "20 MB" 而实际上限 25MB（`document_service.py:44`）。
- 影响：改扩展名的恶意文件进入解析器；超大/压缩炸弹文件可卡住同步 worker。
- 建议：校验 MIME + 文件签名；解析放入 `asyncio.to_thread` + 超时；修正文案。

**P1-5 上传路由在 `finally: file.close()` 后读取 `file.filename` / `file.content_type`**
- 证据：`routes/documents.py:91-99`（`await file.close()` 后构造 `Document` 仍引用 `file.filename`）。
- 影响：Starlette `UploadFile` 关闭后属性仍可读，但依赖实现细节，属脆弱写法；配合 P0-2 需一并审查。
- 建议：在关闭前保存 `filename`、`content_type` 到局部变量。

**P1-6 Agent 多轮对话无上下文上限（EC-000 复核新增）**
- 证据：`agent_service.py:113-118,139-150` 多轮消息全量入模，`recursion_limit=10` 只限制步数，未限制历史消息数与总 Token；`max_tokens` 未设置。
- 影响：长会话累计 Token 成本无上限，可被已登录用户用于成本型滥用；与 P1-2 叠加放大。
- 建议：对历史消息做窗口截断/摘要；设置单次 `max_tokens` 与单会话成本上限。

**P1-7 文档处理（Embedding + Milvus 写入）在同步路由内执行（EC-000 复核新增）**
- 证据：`documents.py:238-277` 调用同步 `process_document`；其中 `qwen_embeddings.embed_documents`（`embedding_service.py:37-61`，同步 HTTP）与 `milvus_vector_store.insert_chunks` 均阻塞事件循环。
- 影响：单个大文档处理会阻塞该 worker 上的所有请求；并发上传可放大为可用性问题。
- 建议：移入 `asyncio.to_thread` 或改为后台任务（带状态、重试、幂等键）。
